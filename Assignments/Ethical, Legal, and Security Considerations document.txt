1) Data Protection
Data Protection: How does your web application secure user data? Consider encryption, secure storage, and data access controls.
* We protect data in transit and at rest encrypted when sent and when stored.

* We use a secure database with rules so only logged in users can see their own data.

* We limit what we store to what the app needs such as workouts, water, and progress.

* Admins cannot see private health metrics, only aggregated info if needed.

2) Authentication & Authorization
Authentication and Authorization: What methods are in place to ensure that users are who they say they are, and that they have appropriate access to resources?
   * Passwords are stored safely hashed.

   * We use short lived tokens after login so sessions can’t be easily stolen.

   * Roles: user vs. admin, users only access their own data.

   * Consent flows for Google Fit / Apple HealthKit.

   * Two-step verification is on our roadmap.

________________


3) Common Vulnerabilities (SQLi, XSS, CSRF)
Common Vulnerabilities: Look into common web application vulnerabilities such as SQL Injection, Cross-Site Scripting (XSS), and Cross-Site Request Forgery (CSRF). How does your application defend against these threats?
      * SQL Injection: only safe/parameterized queries no raw string queries.

      * XSS: we clean any user text (usernames) and don’t render raw HTML.

      * CSRF: we use secure cookies/tokens so other sites can’t fake actions.

      * IDOR/Access mistakes: server always checks data ownership per request.

      * Dependencies: we run updates/security scans regularly.

4) Attack Vectors (client-side & server-side)
Attack Vectors: Identify potential attack vectors—ways malicious users might try to exploit your application. This includes looking at both client-side and server-side vulnerabilities.
         * Brute force logins: rate limits and short locks.

         * Stolen tokens: tokens expire quickly, users can logout all devices.

         * Fake workouts/hydration: server validates entries and timestamps.

         * Injected text: we sanitize usernames/comments.

         * Server secrets: keys/passwords stored in secret env vars, not in code.

Ethical Issues
1. Identify any ethical concerns related to your software.
 The main ethical concerns are about user privacy, data safety, and fair use. Since our app tracks fitness and hydration data, we must make sure users understand what information we collect and how it’s used. We also have to make sure no one can use the app to harm or mislead others.
2. Does your software meet users' privacy expectations?
 Yes. Our app only collects the information needed to make the features work  like username, workouts, and hydration logs. We clearly tell users what data is collected and how it’s stored. All private data is encrypted and can be deleted anytime the user wants. We do not sell or share data with anyone outside the app.
3. Could your software result in discrimination based on race, gender, religion, or other factors? How does your software address these concerns?
 No. The app doesn’t use or ask for any personal traits like race, gender, religion, or income. Everyone is treated equally. Achievements and rewards are based only on workouts and progress not personal details. This ensures the app is fair to all users.
4. Can your software be misused by some users to harm others or the public? How do you prevent this?
 We designed the app to prevent harm.
                  * There’s no public chat or comment feature, so users can’t harass or bully others.

                  * All user activity is personal — only the user can see their data.

                  * If we add social features later, we’ll include report, block, and content filters.

                  * We don’t allow cheating tools or false workout entries to keep the system fair.

Security Issues
1. Identify any security concerns related to your software:
 Our main security concerns are data leaks, stolen passwords, and fake accounts. Since users log personal health progress, we must keep that private and secure.
2. Identify sensitive information stored by your software and explain how you plan to protect it:
 Sensitive data includes:
                        * User login (email and password)

                        * Fitness and hydration logs

                        * Optional connected data from Google Fit or HealthKit

We protect this data by:
                           * Encrypting passwords (using hashing)

                           * Using secure HTTPS for all connections

                           * Limiting who can access the database (only the app server)

                           * Allowing users to delete their data anytime

                           * Keeping API keys and secrets hidden in private environment files, not in the code
